---
name: product-rnp
description: Показывает компактный РНП по товарам WB и Ozon. Используй по запросу «РНП», «РНП по товарам» или «РНП по SKU» для кабинета продавца.
---

Вызови инструмент `get_product_rnp` сервера `marketplaces-ru-readonly`.
Перед самостоятельными расчётами прочитай `explain_business_methodology`.
Для арифметики доступны `calculate_business_pnl`, `allocate_business_expense`
и `forecast_business_sales`. Они не загружают данные и не подтверждают полноту
источников. Прибыль допускается только по полному согласованному реестру затрат.
Различай `drr_in_gross_sales` (до возвратов) и `drr_in_net_sales` (после возвратов);
историческое поле `drr_in_sales` означает базу после возвратов.
Общие расходы оставляй на уровне бизнеса, пока правило распределения не выбрано
явно. Нашу методику не называй точным воспроизведением закрытого алгоритма MPSTATS.
Сбор данных — только по запросу пользователя. Для явного сохранения отчёта
используй `business_report(action='refresh')` с нужными площадкой и периодом.
Для чтения или выгрузки ранее сохранённого используй `saved`/`export`: эти
режимы не обновляют данные из API. Если копии нет, сообщи об этом; не запускай
обновление без запроса. Себестоимость и налоги помнятся независимо от отчётов.
Не предлагай и не запускай расписания или фоновую догрузку.
Проверь `business_inputs.questions`: задай их пользователю в чате, если для
запрошенной прибыли не хватает себестоимости или налоговых настроек. После
ответа вызови `save_business_settings`, передавая только явно указанные
значения и дату начала действия. Это локальные настройки, кабинеты WB/Ozon
не меняются. Перед повторным вопросом читай `get_business_settings`, чтобы
не спрашивать уже сохранённое. Смена цены/режима создаёт новую запись с датой;
не подменяй исторические настройки текущими. Настройки MPSTATS не применяются
без подтверждения пользователя.
По умолчанию он сравнивает последние семь завершённых дней по Москве с предыдущими семью. Передай площадку, дату окончания и поисковую строку только при наличии соответствующего уточнения от пользователя.

Сохраняй результат по отдельным товарам. По умолчанию include_economics=true: отчёт добавляет выкупы, возвраты, продвижение и ДРР по заказам/продажам. limit от 1 до 1000 ограничивает только показ; summary относится ко всему активному кабинету до query и limit. Не складывай summary со строками.

Перед интерпретацией проверь sources, economics_status, advertising_allocation_complete, cabinet и retrieved_at. WB: продажи по дате продажи, выручка priceWithDisc до СПП; рекламная статистика fullstats, без медийной рекламы. Ozon: предварительные продажи по дате начисления (commission.sale_amount), не окончательная реализация и не прогноз. Продвижение Ozon — явно перечисленные виды начислений, не идентичная MPSTATS категория расходов и не Performance. Нераспределённые суммы остаются в summary.unallocated_advertising_rub, по товарам не размазываются. При неполном распределении рекламные расходы и ДРР SKU — null.

В текстовом клиенте покажи отдельные таблицы WB/Ozon: артикул/SKU, заказы (шт./₽), выкупы, возвраты, продвижение, ДРР заказов/продаж. Начни с восьми строк. null показывай прочерком, никогда нулём. ДРР = расходы / положительная база × 100; итог — отношение сумм, не среднее процентов. Выкупы недели могут относиться к более ранним заказам; не дели их на заказы недели для процента выкупа. Прибыль не рассчитывается. Для быстрого отчёта только по заказам передай include_economics=false.

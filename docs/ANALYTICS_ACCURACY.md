# Правила точности аналитики

Добавлены четыре инструмента чтения. Они не меняют цены, рекламу или данные кабинетов.

- `explain_marketplace_metrics`: значения известных полей привязаны к площадке и
  operation_id. Неизвестные поля перечисляются отдельно. Справочник намеренно
  частичный: он не заявляет поддержку всех полей каталогов.
- `get_ozon_finance_audit`: загрузка начислений Ozon по дням через актуальный
  `/v1/finance/accrual/by-day` за интервал в одном календарном месяце. Проверяются пагинация,
  дубликаты ID и числовые суммы. Суммируется `total_amount.amount` со знаком, компоненты операции
  повторно не складываются. Отдельно показаны операции без SKU и с несколькими SKU.
  Это баланс начислений, а не прибыль. Валюта берётся из `total_amount.currency`; смешанные валюты блокируют сумму.
- `check_financial_summary`: расчёт по уже подготовленным фактическим продажам
  и непересекающимся расходам. Неизвестные себестоимость, реклама, налоги,
  прочие расходы и корректировки не заменяются нулями. По умолчанию
  `complete=false`: прибыль не вычисляется до подтверждения полноты вызывающим
  агентом. Это проверка арифметики, а не автоматический аудит исходных данных.
- `reconcile_marketplace_totals`: сверка сумм с обязательным совпадением кабинета,
  площадки, валюты, периода, типа даты и смысла показателя. Дополнительные
  параметры охвата также должны совпадать. Суммы заказов и продаж не сопоставимы.

## Перед каждым выводом

1. Проверить активный кабинет через `*_list_cabinets`.
2. Зафиксировать источник, период, поле даты и валюту. Дата заказа и дата
   финансовой операции не взаимозаменяемы. Финансовый инструмент использует дату начисления Ozon без пересчёта в дату заказа.
3. Вызвать справочник для точного endpoint; неизвестные поля проверить по
   официальной документации. Название `revenue` само по себе не означает продажи.
4. Проверить все страницы, ограничения выдачи и полноту. `truncated=true`
   запрещает вывод об итогах всего кабинета. Обрезка отображения — отдельное понятие.
5. Разделять фактические, прогнозные и предварительные цифры. Закрытый день
   не гарантирует окончательность финансового отчёта.
6. Не складывать итог операции с составляющими. Реклама, уже включённая в
   расходы площадки, не вычитается повторно. Скидки, компенсации и возвраты
   сохраняют смысл и знак источника.
7. Общие расходы не распределять по товарам без явного правила. Нераспределённую
   сумму показывать отдельно. Налоги и себестоимость требуют данных продавца.
8. Сверять финансовые итоги с выгрузкой кабинета за одинаковый период и охват.

## Исправления полноты

РНП больше не заканчивает выгрузку на короткой странице: offset увеличивается
на фактическое число строк. Общая пагинация отклоняет ответ без ожидаемого массива
и отмечает зацикливание курсоров как неполную выгрузку.

## Ограничения

Это основа контроля точности, а не доказанное равенство MPSTATS по функциям.
Пока нет автоматической сверки начислений с независимой выгрузкой Ozon, единого
отчёта о прибыли WB/Ozon по SKU с историей себестоимости, автоматической загрузки
налогов продавца и проверки всех метрик всех endpoint. Сверка с реальными
выгрузками кабинета обязательна перед заявлением о точности финансовых итогов.

Источники: [Ozon Seller API](https://docs.ozon.ru/api/seller/),
[пояснение Ozon к revenue и ordered_units](https://dev.ozon.ru/news/252-Izmeneniia-v-rabote-metoda-v1-analytics-data/),
[WB Analytics API](https://dev.wildberries.ru/openapi/analytics).

Финансовые методы `/v3/finance/transaction/list` и `/totals` удалены из каталога:
они отключены Ozon. Обход `last_id` выполняется последовательно по дням.
Пустой курсор означает исчерпание страниц по сигналу API, но не доказывает
окончательность начислений или согласованность снимка при обновлении.
[Официальное уведомление Ozon](https://dev.ozon.ru/news/783-Izmeneniia-v-metodakh-dlia-raboty-s-finansovymi-otchetami-v-Seller-API/).
